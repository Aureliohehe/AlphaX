# AlphaX 工程化规划

目标是把现有量化研究仓库建设成可安装、可验证、可追溯、可恢复的研究工程。按阶段推进，每一步记录改动、验证结果和未完成项，保持现有研究口径与命令入口兼容。

## 验收原则

- 新机器可以按文档安装，并运行无需行情下载或模型密钥的测试。
- 每次代码变更有自动回归检查；研究行为变化必须独立说明。
- 每次正式实验关联代码、依赖、输入数据、配置和完整产物。
- 失败实验可诊断；恢复执行不能覆盖冻结决策或引入未来信息。
- 数据时点问题与软件工程问题分别验收，不以测试通过代替数据可信度认证。

## 阶段与顺序

| 阶段 | 工作 | 验收标准 | 状态 |
| --- | --- | --- | --- |
| 1A 核心环境与自动检查 | 根目录依赖定义、核心依赖锁定、CI、离线集成测试入口 | 独立虚拟环境安装成功；全部核心测试通过；CI 配置覆盖 Python 3.10 和 3.13 | 已完成 |
| 1B 可选依赖与示例 | 分别锁定 LLM 和 Qlib 环境，增加真实库集成检查、独立离线示例；引入静态检查基线 | 可选环境独立安装；无需外部 API 的库集成通过；示例保留可检查产物 | 本地验收通过，新增 CI 待运行 |
| 2 共享包与模块边界 | 从 Miner 抽取因子 DSL、指标、生成客户端和注册表；逐步移除 sys.path 修改 | 原有 CLI 兼容；现有回归通过；核心模块可直接导入 | 进行中，因子 DSL 已抽取 |
| 3 配置与实验协议 | 统一配置校验、产物 schema 版本、实验 ID 和索引；统一各研究分支接口 | 旧产物可读取或有明确迁移；可按输入、配置和代码版本定位实验并比较结果 | 进行中，已接入主流水线、离线示例、CSI300 因子研究和中低频研究 |
| 4 长任务与 LLM 可靠性 | 阶段检查点、安全续跑、原子落盘；请求追踪、响应回放、限流重试、费用预算 | 中断后恢复结果与连续执行一致；拒绝输入变更；重复请求不会静默重复计入结果 | 进行中，主流水线支持全程续跑，LLM 请求可靠性待实现 |
| 5 数据质量与更新 | 数据版本、时点和覆盖率门禁；历史成分、退市报价、复权及代码映射检查 | 未通过必要检查的数据不能进入正式研究；数据更新可审计、可回退 | 待开始 |
| 6 发布与维护 | 版本与变更记录、兼容策略、故障手册、产物归档；确定授权方式 | 干净环境按发布说明复现参考流程；失败定位和恢复有明确步骤 | 待开始 |

阶段 1A 使用现有合成数据集成测试验证 Miner → Screener → Trader，不将模拟的模型调用称为真实 LLM 或 XGBoost 集成验证。完整可选依赖环境在 1B 单独处理。

阶段 2 按模块小步迁移，每一步保留兼容入口；不在一次重构中改动因子准入或回测规则。阶段 3 完成后再实现阶段 4，避免为不稳定的文件格式建立恢复协议。

阶段 5 的外部数据采购和授权取决于具体供应源。先实现现有数据的可执行检查，缺失的历史数据保留明确状态。项目 LICENSE 的授权选择需由维护者确定。

## 后续运行与实盘方向

研究工程稳定后，再评估定时调度、运行告警和模拟盘。券商接入、订单幂等、成交回报、持仓对账、资金限制及紧急停止作为独立阶段设计，不与研究工程验收混在一起。Web 界面、数据库和容器按实际运行需求引入。
